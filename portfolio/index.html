01 / Operational software · public demo

GrizzWorks

  • JavaScript
  • Shared data model
  • Shop LAN
Try the sample shop ↗

Problem: A shop needs to move between jobs, work orders, inventory, and invoices without tracking the same work in multiple places.

Design decision: Share the business logic between a browser-only demo and a design for shared LAN use. Posted documents are corrected by reversing entries rather than rewriting history.

What to try: Open a job, follow a quote into an invoice, and compare the editable shop view with the wall-board display. The public build stores sample changes in your browser. The dashboard source includes the shared data model.

02 / Infrastructure · hands-on lab

Local infrastructure lab

  • Proxmox VE
  • Ubuntu Server
  • Docker
  • Tailscale
Inspect the lab hardware ↗

Problem: I needed an environment to try deployment and access patterns without depending on a hosted service for every experiment.

Design decision: Run Ubuntu guests on Proxmox on a Dell PowerEdge. Use Docker for app services and Tailscale for private remote access to locally hosted systems.

What to review: The lab describes the hardware, the service stack, and the checks I consider before handing off a deployment.

03 / Product delivery · live app

AFT Forge

  • TypeScript
  • React
  • Offline PWA
  • GitHub Actions
Open AFT Forge ↗

Problem: A fitness planner should work from a phone without requiring an account or reliable network access.

Design decision: Ship an installable web app that stores profiles and logs on-device. GitHub Actions builds the app and checks that the static artifact includes its manifest, service worker, and icons before publishing.

What to review: Try the first-run flow and see how the Pages workflow publishes the compiled app alongside the rest of the site.
